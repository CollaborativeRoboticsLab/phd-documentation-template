\chapter{Contribution 1}
\label{ch::Contribution1}

As discussed in Chapters \ref{ch::Introduction} and \ref{ch::LiteratureReview}, the SOTA robotic systems can mainly be categorised under Learning-based systems \cite{wang_navistar_2023, wang_feedback-efficient_2022}, behaviour-based systems \cite{iovino_comparison_2024}, or Foundation model related systems \cite{rana_sayplan_2023, izzo_btgenbot_2024, brohan_rt-1_2023, brohan_rt-2_2023}. Learning-based systems and Foundation model-related systems rely on datasets \cite{wang_navistar_2023, wang_feedback-efficient_2022, brohan_rt-1_2023, brohan_rt-2_2023, izzo_btgenbot_2024} that contain various robotic activities, enabling the learning of controlling the robot and interacting with the environment. In contrast, behaviour-based systems utilise rule-based knowledge and predefined execution plans to control the robot and interact with its environment.

Due to humans' dynamic nature, robot systems also need to be able to adjust their execution dynamically when used in human-robot interaction scenarios. Failure to do so can result in scenarios such as the \textit{Freezing Robot Problem} and the \textit{Reciprocal Dance Problem} \cite{trautman_robot_2015}, which are widely studied in Socially Aware Navigation (SAN). Due to the nature of learning-based systems, by including human interaction-related data \cite{wang_navistar_2023} in the dataset, they can enable the robotic system to learn about interacting with humans. However, to dynamically interact, a large number of interactions need to be in the dataset, making the dataset rather large and the learning system rather complex. RT1 \cite{brohan_rt-1_2023} and RT2 \cite{brohan_rt-2_2023} utilise such datasets that were collected via the collaboration of many research organisations.

Another approach, as discussed in the sections \ref{sec::LiteratureReview::RobotControlLLM}, \ref{sec::LiteratureReview::RobotControlVLM}, \ref{sec::LiteratureReview::RobotControlVLN}, \ref{sec::LiteratureReview::RobotControlVLA} is to improve the behaviour-based systems by integrating them with foundational models to generate execution plans dynamically based on the environmental stimuli or human interaction. One of the most popular approaches is to generate Python code snippets \cite{liang_code_2023, Yuan_2024} or to generate code-like structures \cite{macdonald_language_2024, singh_progprompt_2022, cao_robot_nodate} that can parse to identify the required robot behaviours.

This contribution chapter proposes a new behaviour-based planning system that addresses the issues discussed in Sections \ref{sec::contrib1::literature} and \ref{sec::LiteratureReview::RobotControlLLM}. These issues generally arise when using current behaviour-based systems with LLMs due to design incompatibilities, as explained.

One of the main requirements of a behaviour-based system is the ability to represent and standardise the robots' skills, behaviours, and capabilities. This enables the behaviour-based system to be adaptable across different robots and building systems for human interaction. Various skill and behaviour representations exist in robotics, ranging from rigid instructive systems that are difficult to adapt to flexible models that allow adaptation but struggle with symbolism and grounding issues \cite{chen2024language, olivares2019review}. As robotics evolves, the need for a standardised framework for how robot skills are represented, executed, and integrated into systems becomes more apparent, especially in the context of robots geared for HRI where the complexity of interactions, role differentiation, morphology, and spatial proximity introduce additional requirements for skill representation \cite{yanco2004classifying}.

Due to these reasons, the Capabilities2 framework is presented, an upgraded and re-implemented version of the original Capabilities package \cite{woodall2014ros}, reaffirming its continued relevance in the current robotics landscape. Capabilities2 offers a generalised, adaptable framework for representing skills, building relationships between them, and enabling flexible, skill-based intelligence within the ROS2 ecosystem. Enhancing the original design addresses previous limitations and introduces features such as an abstracted database handler, an object-relational mapping (ORM) for capability models, and a plugin architecture for capability execution. This system is the foundation for the behaviour-based planning system proposed in this chapter.

Additionally, the Prompt Tools system is presented as a robot-oriented ROS2-based toolset that provides connectivity with LLMs. In addition to standard functionalities like prompt and chat options, this toolset provides new functionalities such as prompt caching to optimise token usage and reduce latencies.

The capabilities2 Fabric is the last subsystem system presented in this contribution chapter. It extends the functionality of the capabilities2 framework with new functions such as execution plan parsing and capability chaining, allowing the capabilities2 framework to function as a behaviour-based planning system.

The remaining sections in this chapter will be structured as follows. The section \ref{sec::contrib1::literature} focuses on discussing and evaluating the related concepts and similar systems based on literature. The section \ref{sec::contrib1::methodology} focuses on the design and implementation of the new behaviour-based planning system. The system comprises three main components, each discussed in a separate subsection. Subsection \ref{sec::contrib1::methodology::Capabilities2} explains the re-implementation of the capabilities2 framework. Subsection \ref{sec::contrib1::methodology::PromptTools} discusses the Prompt Tools system used to connect with LLMs both online and offline. Subsection \ref{sec::contrib1::methodology::Fabric} presents the design and implementation of the Capabilities2 Fabric. Subsection \ref{sec::contrib1::methodology::behaviour} further discusses the integration of the three subsystems to achieve the functionality of the behaviour-based planning system. Finally, the subsection \ref{sec::contrib1::methodology::dynamic-generation} will discuss the functionality as a generative behaviour-based planning system. The results of the evaluations and a discussion about said results are presented in Section \ref{sec::contrib1::results}, while, finally, in Section \ref{sec::contrib1::conclusion}, conclusions are discussed, including the remaining future work related to this contribution.
